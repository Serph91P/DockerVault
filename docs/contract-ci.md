# Real contract / roundtrip CI

The `Tests` workflow runs the following distinct gates. They are not interchangeable:

- **Real HTTP app backup and restore, no seeded catalog**: `python3 backend/tests/run_backup_roundtrip.py dockervault:test` starts a uniquely named `--rm` product-image container with no host Docker socket or published ports. `runtime_backup_roundtrip.py` uses nginx → setup/login → target API → backup API → real archive and completed catalog → source mutation → restore API → byte comparison. It repeats with real age/OpenSSL encryption. Each plain/encrypted case also syncs through the native local provider, deletes the local archive (and removes only the owned fixture's retained local sidecar), restarts the actual supervised backend, logs in again, and restores from the persisted remote-only catalog. It checks source bytes, nested layout, directory symlink and temporary cleanup. Any HTTP/pipeline/byte assertion fails the integration job on native amd64 and arm64.
- **Provider/catalog restart contracts, not archive creation or restore**: `test_sync_restart.py` drives `runtime_sync_probe.py` with intentionally synthetic opaque bytes to test manual sync/retry, exact sidecar identity and file-backed catalog recovery across process lifetimes. Those tests do **not** exercise app backup creation, tar/crypto correctness or the restore API; the HTTP image gate above does.
- **Standalone encrypted recovery**: `runtime_recovery_instructions.py` executes the published age/OpenSSL commands in the built image, independently of app restore.
- **Interruption/migration and bounded browsing**: native Docker cancellation, crash/restart, repeated/interrupted SQLite migrations, full provider roundtrips and large plain/encrypted/local/remote archive paging remain separate canonical regressions. Browsing retains at most one bounded member window; preparation, worker settlement and cleanup share capacity.
- **Frontend caller contracts**: MSW reflects real API behavior, including DELETE 200, explicit clears and bounded plain/encrypted archive page parameters/headers. The actual browser can move forward and back beyond the default 2000 entries without accumulating all pages.

## Dependency scan policy

`pip-audit` is blocking. Npm audit is also blocking on execution/parse/schema errors and every **new or changed high/critical** finding, including a new advisory on an already-excepted package. There is no blanket `continue-on-error`. `backend/tests/check_npm_audit.py` preserves the full raw report as a CI artifact and matches only `docs/npm-audit-exceptions.json`: exact installed versions/nodes, advisory URLs, ranges and severities, tracking issue, reason and expiry. Removal of known findings is allowed; expansion is not. Policy tests inject unknown high and critical findings, change a known advisory/range/severity/version, expire an exception, and inject an audit error; all must fail closed.

The temporary baseline contains 14 high package findings (33 total including lower severities) from the unchanged dependency tree. Each entry expires on 2026-12-03 and tracks #178. Reasons distinguish browser runtime dependencies (Axios, React Router, Zod), Node-only transitive paths and development/build tools. **This is deferred known debt, not a reachability exemption or declaration that the application is secure.** Browser advisories may remain reachable; build-time packages can still affect CI. No dependency upgrade or broader security remediation is smuggled into this backend contract.

Mypy and the existing advisory Trivy/SARIF steps remain nonblocking and must be reported separately from successful mandatory tests. No scan's `continue-on-error` means security success.
